# 交流会マッチング

交流会メンバー同士が気軽につながれるマッチングサービスのデモアプリです。

## 主な機能

- **今日のおすすめ** — 相性スコア順のスワイプ風カードデッキ(スキップ / 話してみたい)
- **メンバー一覧** — 新着メンバー / 今週のピックアップ / カテゴリ別(業種タブ切り替え・並び替え対応)
- **検索・絞り込み** — 名前・会社名・タグ・自己紹介文からのキーワード検索、業種タグでの絞り込み
- **いいね(話してみたい)** — 登録ユーザー同士で実際にいいねを送り合い、相互いいねでマッチング成立。相手からのいいねは「♥ あなたにいいね」として表示
- **メッセージ** — マッチングした相手との1対1チャット(LINE風UI・既読・未読バッジ・スタンプ)。閲覧・送信はマッチング済みの2者のみにAPI層で制限
- **いいねリスト** — 送ったいいねの一覧と取り消し(ブラウザの localStorage に保存)
- **プロフィール詳細** — カードをクリックすると詳細モーダルを表示(相性スコア表示)
- **交流会カレンダー** — 月表示のイベントカレンダーとイベント一覧(月送り・参加登録対応)
- **実績カウンター** — スクロールに合わせてカウントアップするアニメーション
- **無料会員登録フォーム** — デモ用。入力内容は localStorage に保存
- **レスポンシブ対応** — スマートフォン〜PC まで対応

## 紹介先早見表・紹介診断(`/referral/`)

会員同士のリファラル紹介を増やすための会員限定ページです(要ログイン)。

- **紹介先早見表** — 会員ごとに「事業内容/求める紹介/こんな話が出たら(トリガーワード)/活動範囲(対面・オンライン)」をカードで一覧化。キーワード検索・業種・対応エリアで絞り込めます
- **紹介診断(マッチ率)** — 会話で出た話について5つの質問(話題・相手のタイプ・業種・エリア・会い方)に答えると、会員ごとの一致度(0〜100%)を計算し、上位5名を理由つきで表示。一覧を一致度順に並べ替えることもできます
  - 配点: 話題50 + 業種15 + 相手のタイプ10 + 会い方・エリア25(キーワード一致で+10)。話題もキーワードも一致しない人は30%で頭打ち
- **紹介文をコピー/LINEで送る** — 診断した話題を織り込んだ紹介文を自動作成し、ワンタップでコピーまたはLINEで共有
- 名簿は BT-EX5 の会員27名(実在メンバー)。山本 捷真以外は名簿の肩書き・所属チームのみ反映済みで、求める紹介・活動範囲などは「準備中」。業種と診断用の話題タグは肩書きからの仮設定なので、管理者ページで確認してください

## 名簿の管理(`/admin/`・管理者のみ)

- メンバーの追加・編集・削除、事業内容/求める紹介/トリガーワード/活動範囲/紹介診断のタグ(話題・業種・相手のタイプ)の入力ができます
- 権限はサーバー層で確認します(一般会員は画面も API も `FORBIDDEN_ADMIN`)。デモでは `demo@kouryukai.jp` が管理者です
- 「JSONを書き出す/読み込む」で名簿を保存・移行できます(デモの名簿はブラウザ内保存のため)
- 初期名簿は `referral/data.js` の `REF_SEED_MEMBERS`。名簿が未作成のときに一度だけ投入され、以降の変更は管理者ページで行います

## リアルタイム同期とデータの範囲(重要)

- メンバー登録・いいね・マッチング・メッセージは共有DB(デモでは localStorage)に保存され、**BroadcastChannel / storage イベント+ポーリング**で別タブへ即時反映されます
- セッショントークンはタブ単位(sessionStorage優先)で保持するため、**同一ブラウザの別タブで別アカウントに同時ログイン**してやり取りを試せます
- デモ実装のため共有範囲は**同一ブラウザ内**です。**別の端末・別のブラウザ間**でのやり取りには実バックエンド(GAS / Firebase 等)が必要で、`auth/api.js` の `API_BASE_URL` を設定するだけで同一契約のAPIに差し替えられます

## ログイン機能

`docs/specs/login-page-detailed-spec-v3.md` を設計仕様として実装しています(適用方針は `docs/specs/README.md` 参照)。

**アプリ本体(トップページ)はログイン必須です。** 未ログインでアクセスするとログインページへリダイレクトされ、ログイン後にアプリが表示されます。

- **ログインページ** (`/login/`) — label 完備・placeholder 不使用・パスワード表示切替(aria 同期)・「ログイン状態を保持」(オフ12時間 / オン30日、`=== true` 厳密判定)・二重送信防止・AUTH_FAILED 時のみパスワード欄へフォーカス
- **マイページ** (`/portal/`) — `guardPage()` による保護ページ。未ログインは `?next=portal` 付きでログインへ。`?next=` は許可リスト(`['portal']`)照合で不正値を丸め、任意URLは受け取らない
- **パスワード再設定** (`/password/reset/`) — 登録の有無にかかわらず常に成功応答(アカウント列挙耐性)
- **セッション** — 保存はトークン文字列のみ(キー `kouryukai-auth-session`)。ログイン成功ごとに新規ランダムトークンを発行(Session fixation 対策)。有効性判断は verifySession のみ
- **サーバー判定**(デモ実装 `auth/mock-server.js`)— 5回失敗で15分ロック / 失敗理由は AUTH_FAILED・LOCKED に集約 / 未登録アドレスにはダミー照合 / verifySession 失敗は SESSION_INVALID 単一コード
- **デモアカウント** — `demo@kouryukai.jp` / `kouryukai-demo-2026`(ユーザーDBもブラウザ内 localStorage)

実バックエンド(GAS 等)へ接続する場合は `auth/api.js` の `API_BASE_URL` を設定するだけで、モックの代わりに text/plain POST で同一契約の API を呼びます。

## 技術構成

ビルド不要の静的サイトです(HTML / CSS / Vanilla JavaScript)。

```
index.html            … ページ本体
css/style.css         … スタイル(クリーム×ゴールド×朱赤の配色)
js/data.js            … サンプルデータ(メンバー・カテゴリ・イベント)
js/app.js             … アプリケーションロジック
login/  portal/  password/reset/ … 認証関連ページ
referral/             … 紹介先早見表・紹介診断(data.js に初期名簿)
admin/                … 名簿の管理(管理者のみ)
auth/                 … 認証共通層(api / session / ui / mock-server / 各画面ロジック)
docs/specs/           … 仕様書(実装の正)
```

## 動かし方

そのままブラウザで `index.html` を開くか、任意の静的サーバーで配信してください。

```bash
# 例: Python の簡易サーバー
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

## 備考

- メンバー・イベントはすべて架空のサンプルデータです。
- いいね・登録情報はサーバーに送信されず、ブラウザ内(localStorage)にのみ保存されます。
