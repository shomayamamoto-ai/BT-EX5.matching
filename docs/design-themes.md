# デザインの切りかえ(やわらかいデザイン ⇔ 元の黒×金)

## しくみ

| 対象 | やわらかいデザイン | 元の黒×金 |
|---|---|---|
| サイト全体 | `assets/soft.css`(`link[data-theme="soft"]`)を読みこむ | `assets/theme.js` がこの link を無効にする(読みこまない)ので、前の見た目にそのまま戻る |
| 定例会のスライド・タイマー | `.pr-run` に `deck-soft` クラスを付け、`assets/deck-soft.css` が効く | `deck-soft` を付けない(`assets/deck-soft.css` は何も効かない) |

- 選んだデザインは、その端末(ブラウザ)の `localStorage` に覚える。
  - サイト全体:`btex5-theme`
  - 定例会のスライド:`btex5-deck-theme`
- 値は `soft`(はじめ)か `classic` のどちらか。
- 切りかえる画面は次の2つ。
  - アプリの マイページ →「デザインの切りかえ」:サイト全体とスライドの両方。
  - プレゼンの画面 →「スライドのデザイン」:スライドだけ。
- 元の黒×金にしたときは、次のものも出さない。
  - アプリの各画面の頭(英字の筆記体と画面名、`app/core.js` の `addHero`)。
  - 見出しの英字の筆記体(`data-en`)。

## 確かめたこと

- 定例会のスライド全44枚(43画面)で、「元の黒×金」と、やわらかいデザインを入れる前のスライドを、画面の画像で1点ずつくらべた。
  - 上の時刻の帯を除いて、40画面は同じ。
  - 差が出た3画面は、どれもデザイン以外の理由。
    - 用語のポップアップと休憩の確認は、動きの途中で撮った時間のずれ。
    - アンケートの QR コードは、中のアドレスの違い。

## すべてのデザインを、やわらかいデザインを入れる前にもどすとき

- 入れる前のサイトのデザインは、コミット `6a38cc4` の時点。
- 次のコミットで入れたもの。
  - `9cd42d2`:サイト全体のやわらかいデザイン。
  - このファイルを足したコミット:スライドのやわらかいデザインと切りかえ。
- `assets/soft.css` と `assets/deck-soft.css` の link を外すと、見た目は元に戻る。
  - あわせて `app/core.js` の `addHero` と、各ページの `data-en` の英字を外す。
